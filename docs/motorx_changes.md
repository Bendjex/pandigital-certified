## C.9 The optimised motor X (02–03/11/2026): what changed and why it is correct

Motor X with n = 8 in any order needed 40–70 min per top-level split (127 splits per constant). The measurement in this session showed that the time did not go to motor B but to the window lookups. All changes below keep Theorem X: each one either returns the same pairs as before, or replaces a superset by a smaller superset whose covering property is proved in one line.

1. **Tiered index (`qx.IndexT`).** `Index.look` returned the pairs (window, entry) with B ≥ lo and A ≤ hi. It found the candidates by a sorted search with a slack equal to the largest width among the "narrow" entries, where "narrow" meant width ≤ 10⁻³(1 + |A|). One entry with |A| ≈ 10³⁰⁰ allowed widths of about 10²⁹⁷, so the slack became infinite and every lookup scanned the whole table. On split 8 of n = 8, 393 s of 458 s were spent there. `IndexT` returns *exactly the same set of pairs* (tested on random tables with every kind of entry, `t_index.py`) from separate classes of entries:
   - finite enclosures in tiers of absolute width, each sorted by A, where B ≥ lo implies A ≥ lo − w_max;
   - half-lines [−∞, B], sorted by B;
   - half-lines [A, +∞], sorted by A;
   - the whole line, and the exact zeros.
2. **Exchange of roles (`combine_swapped`).** When the query side S₂ of a split is itself within the table sizes and its table is much smaller than the table of S₁, the loop runs over the S₂ table. The preimage window of s is pre(f′, l, w), with f′ = SW[f] the form with the operands exchanged (s+l, |s−l| and s·l are symmetric, and s/l ↔ l/s, s^l ↔ l^s, s^−l ↔ l^−s), so f′(l, s) = f(s, l). By Lemma X3 for f′, every pair with f(s, l) ∈ w is found. Each pair is then treated exactly as before: the same `fwd(f, s, l)`, the same exact decisions and the same filters. On artificial windows with ~30 000 hits the multiset of hits is identical with and without the exchange.
3. **Out-of-range parts of the windows for (V, V) pairs.** By Lemma X1(c), a pair of in-range values contributes to NE(S) only through an out-of-range result. An out-of-range u satisfies ln u < ln 10⁻³⁰⁰ ≤ LN_LO_HI or ln u > ln 10³⁰⁰ ≥ LN_HI_LO. So the (V, V) part is queried only with [lo, min(hi, LN_LO_HI)] and [max(lo, LN_HI_LO), hi] (`qx.out_parts`), and every hit keeps the index of its window.
4. **The exact zero in recursive V queries (correction of a gap).** A V query above the table size clipped its windows to the range, so a window [−∞, h] lost the value 0, although 0 ∈ V(S) for many S. Theorem X needs it: for u ∈ NE(S₁), the value u + 0 = |u − 0| = u is produced by the split with 0 ∈ V(S₂). The recursive V query now also returns the exact zero for every window with lo = −∞, as a possible member; this is a superset. No closed cell changed (the regression below).
5. **Exact members of V(S) without motor B for |S| > t_V (`exact_V`).** The exact decisions of C.5 need the exact values of V(S) in an enclosure. For |S| > t_V they came from a motor B query on S, which takes 1 s for 5 digits and 70–150 s for 6. They now come from motor X's own recursion for kind V in provenance mode, with every returned derivation evaluated exactly (the exact members of its table classes, Lemma 14, and motor B's exact arithmetic). *Proof that nothing is lost:* a value y ∈ V(S) in the window is a literal or f(a, b), with a ∈ V(S₁) in a class i of motor A (Theorem A) and b ∈ V(S₂) covered by a derivation D_b of the sub-query (induction). By Lemma X2 the enclosure of (i, f, D_b) meets the window, so this derivation is returned and its exact evaluation contains f(a, b). Tested against motor B on 34 387 values: 0 missed (`t_exactv.py`).
6. **Persistent cache of the N tables.** N(S) is a deterministic function of the code and of the V tables of the subsets of S. Each table is stored on disk under a name that contains a SHA-256 fingerprint of all those inputs (`motorx.ncache_path`), so a stored table is used only where the same computation would produce it again. A damaged file is recomputed.
7. **Parallel exp/ln bounds.** The elementwise C loops of `xlib.c` are split with OpenMP over large arrays. Each element is computed by the same function, so the results are identical bit for bit (checked on 10⁶ inputs, and between Linux and Windows/wine).

8. **Second-level preimages of s^l and s^−l (`qx.pre2`).** If sign(ln s) = σ and ln|ln s| ∈ [M, N], then ±l·ln s ∈ [α, β] is l·|ln s| ∈ [a, b], with (a, b) = (α, β) or (−β, −α) according to the form and σ. So b > 0 is needed, and ln l ∈ [ln a − N, ln b − M] (lower end −∞ if a ≤ 0). Both this window and the one of Lemma X3 contain every admissible l, so their intersection does too. It is not applied when the window contains ln 1 = 0 (l = 0 gives s⁰ = 1), or when s is 0 or exactly 1. Why it matters: a double-exponential s, e.g. ln s = −1.248·10¹³, has a first-level width of several ulps of 10¹³, but its ln|ln s| = 30.155… is known to 16 digits, so the first-level window of l was up to e^(10⁴) times too wide. Test `t_pre2.py`: 14 007 cases, 4501 of them with f(s, l) in the window, 0 missed.
9. **Second-level constraint on the bases of l^s and l^−s (`qx.pre_level2`).** ±s·ln l ∈ [α, β] with ln s ∈ [A, B]. If the window does not contain 0, ln l has a known sign. For sign +1 (a = α > 0), ln l ∈ [a/s, b/s] gives ln ln l ∈ [ln a − B, ln b − A]; for sign −1 (b = β < 0), ln|ln l| ∈ [ln(−b) − B, ln(−a) − A] (with (a, b) = (−β, −α) for l^−s). A table entry, or a result of a recursive query, whose sign is known and whose second level is disjoint from this interval (or of the other sign) holds no admissible l and is dropped. Entries of unknown sign are kept. Test `t_level2.py`: 30 000 cases, 17 398 with f(s, l) in the window, 9452 with the constraint active, 0 missed.
10. **The exact members of V(S) near 1 (`qx.near1`).** For |S| = 5 (above the size of the V tables), a recursive V query with a window inside [−δ, δ], δ = 10⁻¹¹, is answered by a table of exact values instead of the recursion. The table is a motor B query (Lemma 14) with the window [1 − 2δ, 1 + 2δ], which contains every v with |ln v| ≤ δ, since e^δ − 1 ≤ 2δ and 1 − e^(−δ) ≤ δ. Each value is decided:
    - it is exactly 1 (exact sign of v − 1): flag O;
    - or ln v is enclosed by an Arb ball at 256…65 536 bits. A value certainly outside [−δ, δ] is dropped. One whose ball still contains 0 is kept with the enclosure [−δ, δ] and no second level. The sign of ln v and ln|ln v| come from the ball. When the double bound on one side rounds across 0, it is replaced by 0, which is still valid because ln v has the sign of the ball.

   A window inside [−δ, δ] receives the rows meeting it (`IndexT`, exactly the pairs of the plain test). The same rows give the exact members needed to decide a base of l^s that may be 1 (C.5, `refine_base1`): for an enclosure [A, B] ⊆ [−δ, δ], the members with ln in [A, B] are among the rows meeting it. *Why:* V(56789) has 6.5·10⁶ derivations of values within 10⁻³⁰⁰ of 1, most of them equal to 1. In split 129 of n = 9, the refinement of 59 bases with |ln l| ≲ 4·10⁻¹⁴ cost one exact evaluation of ≈ 2·10⁵ derivations each, 85–240 s apiece. The table of 56789 has 57 991 rows, takes 11 s of motor B, and serves every window, split and constant. Test `t_near1.py`: every exact value found by the recursion itself (near1 off) in 30 windows inside [−δ, δ] is covered by a row; the rows agree with a fresh evaluation of their writings; and the index returns exactly the plain pairs.
11. **One logarithm per distinct window bound (`qx._on_unique`).** `pre2` and `pre_level2` take ln of the window bounds, and these repeat once per table entry in a batch. `ivl.ln_lo` and `ivl.ln_hi` are pure functions of the double, so evaluating them once per distinct value gives the same windows bit for bit (`t_unique.py`, 300 random batches). One recursive V query of split 129 of n = 9 went from 63 s to 1.3 s.
12. **Index keyed by ln|·| for one-signed entries (`IndexT`, version ixT2).** In the tiers of absolute width, an entry with |A| ≈ 10⁷² and width 10⁶⁰ (relative width 10⁻¹²) was a candidate of every window within 10⁶⁰ of it, for instance every window near ln 1. One batch of n = 9 had 4·10⁸ candidates and ran out of memory. Entries with A > 0 are now keyed by (ln A, ln B), and entries with B < 0 by (ln(−B), ln(−A)), in tiers of the width of the key, i.e. of the relative width. A match has ln A ≤ ln hi and ln B ≥ ln lo, so fl(ln A) ≤ fl(ln hi) + ε and fl(ln A) ≥ fl(ln lo) − w_max(1 + 2⁻⁵²) − ε, where ε is a few ulps of np.log. The search uses margins of 2⁻⁴⁰|x| + 2⁻¹⁰⁰⁰ and w_max·2⁻⁴⁰, rounded outward twice, and then applies the plain test to (A, B) itself. So the set of pairs is unchanged: 600 random tables of every magnitude, with signed zeros, subnormals and NaN, against the plain test, and 200 against the original Index, give 0 differences (`t_index.py`). On split 129, the part (V(1234), N(56789)) went from more than 10 GB (stopped by the memory guard) to 0.4 s and 1.3 GB.
13. **Exact differences of overlapping classes in recursive V queries.** A pair (s, l) of classes of V(S₁) × V(S₂) whose difference has the lower bound −∞ (the classes overlap) gave the enclosure [−∞, B] as a value of V(S). Such an enclosure meets every deeper window: |8 − y| with y ≈ 8 produced the hits of type ln u ∈ [0, x] of s^l at the top level. As already done for the out-of-range parts at the top level (want "out"), the difference is now decided with the exact members of both classes (Lemma 14, motor B). An exact zero cannot meet a window of a recursive V query, since these are clipped to the range and 0 is returned separately, before the clipping (change 4). An out-of-range difference is not in V(S). An in-range one is enclosed by its Arb ball. A difference whose sign stays undecided keeps [−∞, B], and a pair whose l is a recursive value keeps its enclosure.
14. **Margins of the dominance rules (C.4.2(6), C.4.3(2), C.4.4(7)).** The three rules asked the second levels to be at least 1 apart. The identities need only strict separation, plus, for the difference, λ_a − λ_b ≥ 1, which is now checked through a rigorous lower bound of ln(e^(M_a) − e^(N_b)). Test `t_fwd2.py`: 2 × 20 000 pairs beyond the double range with second levels 0–3 apart, checked against mpmath at 80 digits, 0 failures. The fraction of informative results (S ≠ 0) went from 80 % to 98 %. `t_fwd`, `t_anchor`, `t_pre`, `t_ancpow` and `t_factor` still pass.

15. **Exact offsets of exact powers (`ivl.factored`, fields OP, OQ).** With a triple X = (FP/FQ)^(FE/FD) (C.4.6(9)), the value u = X + c, with c = OP/OQ an exact rational, is kept exactly:
    - X + q, and (X + c) + q = X + (c + q);
    - |q − (X + c)| = X + (c − q) when X + c > q certainly, i.e. the lower bound of ln(X + c) exceeds ln q;
    - |(X + c₁) − (X + c₂)| = |c₁ − c₂| exactly (the exact zero if c₁ = c₂), for the same triple X; the result is an exact rational and its enclosure is that of the rational.

    A value with an offset is not a power, so the rules for triples (products, powers, equality) ignore it. The channel is kept only for huge X (lower bound of ln X above 40). Below that, X + c₁ and X + c₂ are told apart by their double enclosures anyway, and keeping it for every algebraic X (such as 2^(1/2) + 3) made the table builds far slower. Keeping a statement for fewer values never loses one. *Why:* motor X left 57 420 hits in split 9 of n = 9 (|S₁| = 2). In 53 952 of them, the l of l^(−s) was a difference such as |3^32768 − (9^(4⁷) ± 6)|: equal X, different exact offsets. Its enclosure [−∞, B] met every window. Test `t_offset.py`: 33 622 cases, with 18 292 exact differences and 176 exact zeros, checked against exact rational arithmetic and mpmath at 400 digits: 0 failures.

16. **An exact 1 is also the exact rational 1/1 (`ivl.fwd`, final step).** A result with the flag O (u = 1 exactly) now also gets AP = AQ = 1 with DS = 0. The exact differences of C.4.4(3) only look at the rational channel; an entry such as 1^(.7^(3^16)), flagged O but without 1/1, gave |4 − 1| as an enclosure of ln 3 instead of the exact 3, and then |3 − 3| as [−∞, B]. *Proof:* O states u = 1, and 1 = 1/1. Checked in `t_ancrat.py`: every result with O carries 1/1.
17. **Rule C.4.6(8) with exact rational exponents (`ivl.anchors`).** Take a base q(1 + d), exact (d = 0) or anchored, with q = P/Q, raised to an exact rational t = p/r (r > 1). If P^p and Q^p are exact r-th powers (integer roots, checked by exponentiation), then q^t = (P^(1/r)/Q^(1/r))^p is rational and (q(1 + d))^t = q^t (1 + d)^t. The anchor bound of rule 8 holds with k replaced by t:
    - ln(1 + d) = d(1 + θ₁) with |θ₁| ≤ |d|;
    - z = t ln(1 + d) satisfies |z| ≤ 2t|d|;
    - e^z − 1 = z(1 + θ₂) with |θ₂| ≤ |z|;
    - hence ln|δ′| ∈ ln t + ln|d| ± 2(t + 1)|d|, with t taken outward as pred/succ(p/r), and the sign of δ′ is ±sign(d).

    *Why:* in split 9 of n = 9, (9(1 − d))^(1/2) lost its anchor, and |3 − 3(1 − d)^(1/2)| became [−∞, B]. Test `t_ancrat.py`: 4678 cases against mpmath at 1400 digits, with 2696 anchored and 1031 exact results, 0 failures.
18. **Second-level constraints of the windows passed down the recursion (`qx`, C2PROP).** A window can also carry c2 = (σ, [m, M]): ln u has sign σ and ln|ln u| ∈ [m, M]. This happens for windows beyond the double range, e.g. [DBL_MAX, ∞) with ln ln u ≈ 753.3. Until now c2 only filtered table entries and the final results of a recursive query, so a sub-query could see the half-line ln l ≥ 709 and millions of candidates. `combine` now derives a constraint for l from the constraint on u = f(s, l), for each form:
    - **s^l, s^−l:** l·|ln s| = ±w with ln|w| ∈ [m, M], so ln l ∈ [m − N_s, M − M_s], intersected with the window of `pre2` (C.9.8);
    - **l^s, l^−s:** ln l has the sign of ±w and ln|ln l| = ln|w| − ln s ∈ [m − B_s, M − A_s] (`pre_level2`, now also with c2);
    - **s·l, s/l, l/s** (`level2_lin`): ln l = w − λ, λ − w or w + λ, with |λ| ≤ L = max(|A_s|, |B_s|) ≤ |w|/2. So ln l has the sign of w (−w for s/l), and ln|ln l| ∈ [m + ln(1 − L e^(−m)), M + L e^(−m)];
    - **s + l, |s − l|** with w > 2 and ln s ≤ w − 1: l lies in [u − s, u] (sum) or [u − s, u + s] (difference), so ln l ∈ [w − 1, w + 1]. Hence ln ln l ∈ [m + ln(1 − e^(−m)), M + e^(−m)], and the upper end is M for the sum;
    - **s + l with w < 0:** l ≤ u, so ln|ln l| ≥ m.

    Every constraint is implied by the window and its c2, so every admissible l satisfies it. Constraints are intersected, and a contradictory one gives an empty window. All bounds are rounded outward.

    One more case: `pre2` did not intersect when the first-level window [α, β] contains ln 1 = 0, since l = 0 gives s⁰ = 1. With c2 the sign of w is known, so w ≠ 0 and l = 0 is not admissible. The intersection then applies even though [α, β] contains 0, and the window keeps only its second-level bound. Example from split 45: the window [−5·10⁻³²⁴, 6·10⁻³⁰⁹] with ln ln u ≈ −1609.3, under s′ = 4, gave 615 000 candidates per form. Test `t_c2prop.py`: 16 680 cases, 15 554 with the constraint active, 0 missed; the exact l comes from mpmath. A second run includes windows below the subnormals whose first level straddles 0: 16 659 cases, 13 845 active, 0 missed.
19. **One exact query per class in `resolve_vv` (want "out").** Many recursive values l overlap the same class of s with nearly the same narrow enclosure, for instance many writings of 4 against s = 4. Their exact members are now taken from one exact query on the union of those enclosures, which is a superset for each pair (Lemma 14 / `exact_V`), and filtered by each member's own Arb ball of ln. In split 45 of n = 9 this cut the exact queries from 3594 to 66.

*Implementation note (03/11).* With rational exponents almost every exact power of a rational carries a triple, so the per-row Python loops of `factored` and of the rational-exponent case of rule 8 made a table of four digits take more than 10 minutes. Both are now vectorised: `primitive` and the integer roots are computed once per distinct rational (or pair (P, r)), and the exponent arithmetic uses int64 with an overflow check in floating point (products formed only below 2⁶¹). The statements are the same, and the tests `t_factor`, `t_factor2`, `t_offset`, `t_ancrat` and `t_ancpow` pass unchanged. N(1234) takes 0.3 s and N(12345) 42 s.

20. **A triple with an integer exponent whose value fits is also that exact rational (`ivl.fwd`, final step).** (FP/FQ)^FE with FD = 1 and FP^|FE|, FQ^|FE| < 2⁶⁰ gets AP/AQ = FP^FE/FQ^FE (or the inverse for FE < 0), DS = 0. Example: (3^k)^(1/k) is the triple (3, 1, 1, 1) and is now also the exact 3, so |6 − 3| and |3 − 3| are exact. *Proof:* the triple states the value exactly, and the integer powers are computed exactly (`ipow`, with an overflow check).
21. **Rule C.4.6(7) with an anchored rational exponent (`ivl.anchors`).** Take an exact base q = P/Q ≠ 1 and an exponent t(1 + d), with t = p/r (1 < r ≤ 64, p ≤ 6) anchored, when P^p and Q^p are exact r-th powers. Then q^(t(1+d)) = q^t·q^(td) = q^t(1 + δ′), with δ′ = e^z − 1 and z = t·d·ln q:
    - sign(δ′) = sign(d)·sign(ln q), and the other sign for s^−l;
    - ln|δ′| = ln|d| + ln|ln q| + ln t + ln((e^z − 1)/z), and the last term lies within ±2e^(DN′) as in the integer case, DN′ being the upper bound of ln|z|.

    *Why:* about nine in ten of the hits of split 9 of n = 9 were |3 − 9^(½(1 ± δ))| (69 % of a sample of 400) and the same with 8^(1/3), 4^(3/2), 4^(−1/2), 8^(2/3). Here 9^(1/2) = 3 is rational, but the integer rule did not apply. Test `t_ancrat.py` (second part): 1972 cases against mpmath at 1400 digits, all anchored, 0 failures.
22. **The second-level filter, earlier and also for exact 0 and 1 (`qx.c2_drop`).** A value with the flag O has ln u = 0, which has no sign, and the exact 0 has ln u = −∞ (sign −1, ln|ln u| = +∞). Neither satisfies a constraint c2 with a sign, or with a finite upper end of ln|ln u| in the case of 0. They are now dropped, as are entries with a known sign or second level outside c2. The filter is also applied inside `combine`, as each chunk's hits are produced, not only at the end of the recursive query. It is the same test applied earlier, so only the memory changes: in split 45, the near-1 V query on 456789 kept 12·10⁶ derivations, most of them equal to 1, and the process reached 13 GB.

23. **The exact refinement of a base near 1, narrowed to its preimage window (`qx.refine_base1`, NARROW_REFINE).** For l^s and l^−s whose base l (a recursive value) may be 1 and whose result is wide, C.5 replaces l by the exact members of V(S₂) in l's enclosure [A, B] (`exact_near1`, which for |S₂| > 5 is `exact_V`, the recursion in provenance mode). Now the members are asked only in [A, B] ∩ [α_l, β_l], where [α_l, β_l] is the preimage window of the sub-query that returned l, and under its second-level constraint c2_l (`pre_level2`). *Proof:* by Lemma X3, f(s, l) ∈ w for some s of the class implies ln l ∈ [α_l, β_l]; by C.9.9/18, it also implies that l satisfies c2_l. A member outside them gives no value in the window for any s of the class, so dropping it loses no value, and the hit's enclosure is still an enclosure of every value of the pair that lies in the window. `exact_V` passes c2 down its recursion, which only removes values that fail it (C.9.18). *Why:* in split 45 of n = 9 (S₁ = {1, 2, 3}), s = 2^1000 (written .1^−3 = 1000) makes the window of l^s the point ln l ≈ 1.07·10⁻³⁰¹, while the base's enclosure was [−4.7·10⁻¹⁵, 4.1·10⁻¹⁵]: the exact query over the whole enclosure returned 1.8·10⁷ derivations and the process passed 13.6 GB. With the narrowing the split runs in 23 min and 4.2 GB. Test `t_narrow.py`: for 5-digit sets, against motor B's near-1 rows (every exact member with |ln v| ≤ 10⁻¹¹, Lemma 14), every member inside a random window and constraint is found: 87 501 required rows, 87 501 matched (2 sets × 40 windows; a third set and the 6-digit part were stopped by the memory guard and are to be repeated).

24. **lvl: an exponent or base known exactly through its vector of prime exponents (`lvl.pw`).** A value of `lvl` can carry its exact value as a vector ∏p^a (C.9, independent evaluator) without its rational: (10^(1/2))^6 has the vector {2: 3, 5: 3}, which is 1000. `pw` now uses such an exponent or base as that rational (`exact_of`, which expands a vector with integer exponents and checks the size), when it has at most 400 000 bits; otherwise nothing changes. *Proof:* the vector states that the value is exactly ∏p^a, and with integer exponents that is the rational computed by exact integer arithmetic; replacing an enclosure by the exact value it encloses is valid. An anchored base keeps its anchor (C.9.25). *Why:* the 20 undecided values of split 45, e.g. |(1/5)^−1000 − 5^((√10)^6)| and |2^1000 − 8^((3·(9/10)^(−3/5))^5)|, are exact zeros: lvl had 5^(interval ∋ 1000) against the exact 5^1000, and no precision decides an equality by intervals. Test `t_lvlpw.py`: 2 × 3000 chains B^Y with Y built as products and powers of rational powers whose value is rational, against writings of the same value (exact zero required) and perturbed ones (no false zero, enclosure contains the mpmath value at 200 digits): 2940 equal pairs, all exact zeros; 2060 different pairs, no false zero; 0 problems. With the previous `lvl.py` the same test gives 137 problems out of 300.

25. **lvl: first-order anchors at exact powers (mechanism B).** `lvl` had anchors u = q(1 + σe^D) with q an exact rational and e^D < 2^−(PREC−60) (lvl's own code, C.9). It now also has anchors at an exact power P = ∏p^(a_p) with rational exponents (`apf`), and four rules, all identities with rigorous bounds:
    - *power of an anchor* (`one_pow`): (q(1 + x))^t = q^t(1 + x′) for a rational t ≠ 0, with x = σe^D, |x| ≤ X ≤ 2⁻²⁰. Since ln(1 + x) = x(1 + θ₁) with |θ₁| ≤ |x|, z = t ln(1 + x) has |z| ≤ 2|t|X, and e^z − 1 = z(1 + θ₂) with |θ₂| ≤ |z|: x′ = t x (1 + θ₁)(1 + θ₂), so sign(x′) = σ·sign(t) and ln|x′| ∈ D + ln|t| ± (2X + 4|t|X) (|ln(1 + θ)| ≤ 2|θ|). q^t is the exact power of q's vector times t (rational if its exponents are integers);
    - *anchored exponent* (`pow_anchored`, `exp_near_small`): B^(c(1 + x)) = B^c·e^w with w = c x ln B, |w| ≤ |c| X |ln B| ≤ 2⁻²⁰, e^w − 1 = w(1 + θ), |θ| ≤ |w|; also for an exact rational exponent of many bits e = c(1 + ρ), c the nearest small rational (continued fractions, ≤ 64 bits) and ρ tiny;
    - *near an exact r-th power* (`near_root`): an exact rational q of more than PREC − 64 bits raised to t = a/r: q = M^r(1 + ρ) with M a small rational (integer r-th roots of numerator and denominator), or q = B₀(1 + ρ) with B₀ the nearest small rational; q^t = M^a(1 + ρ)^t or B₀^t(1 + ρ)^t, then the power rule;
    - *exact value ± tiny* (`_rel_tiny`, `_apf_tiny`, `_anc_not_huge`): e ± t = e(1 ± t/e) when t/e < 2^−(PREC−60), for e an exact rational or an exact power; when the exact result would be a rational of more than 400 000 bits, the anchor is returned instead, with the exact statement kept as the offset X ± t (C.9, offsets), so later exact cancellations are not lost. |P − P(1 + x)| = P e^D and |P(1 + x₁) − P(1 + x₂)| = P|x₁ − x₂| for equal P.

    All quantities are mpmath intervals rounded outward; a rule that does not apply returns nothing and the previous rules run, so no case is decided that was not decided before by a rule that is now wrong. *Why:* the undecided values of split 9 of n = 9, e.g. |3 − (|6 − 9^16384|)^(1/32768)|^(−1/50) and |8 − ((4 + (3/5)^4782969)^(3/10))^5|, are not zero but differ from an exact value by about e^−36000 and e^−2.4·10⁶, which needs 52 000 and 3.5·10⁶ bits of plain interval arithmetic. With the anchors they are decided at 400 bits. Test `t_lvlanc.py`: four families (near an r-th power; anchored base to a rational and back to a rational; anchored exponent; exact power ± tiny, times a rational), with ε = (p₁/p₂)^K down to e^−3·10⁶, each result checked against mpmath (in the log domain; for the first family at the full precision of q): 587 + 591 cases (2 seeds), all decided, none outside the true value, no false zero. The earlier tests of `lvl` still pass: `t_lvl` (random expressions against mpmath at 3000 digits), `t_lvlpf` (vectors and offsets) and `t_lvlpw`, 0 bad. 27. **The exact members of a table entry (`motorx.MX.class_members`, 10/11).** The exact decisions (C.5, items 5, 13, 19 and 23, and `hitcheck`) need, for an entry i of the V table of S, a list M′(i) of exact values with this property:

    **(I)** every a ∈ V(S) has an entry i whose statement holds for a and with a ∈ M′(i).

    The statement of an entry is the exact rational P/Q, or A ≤ ln u ≤ B. Until now M′(i) was motor B's answer on the value window [e^A, e^B] rounded outwards (Lemma 14), which gives (I) since it holds every value of V(S) in that window. Near 1 that window is [pred(1), succ(1)] whatever A and B are, because e^A rounds to 1 for |A| < 10⁻¹⁶. So every class within 10⁻¹⁶ of 1 returned all its neighbours: 315 values per class in V(3469), where one or two belong to it.

So some entry i has A ≤ ln a ≤ B (or is the exact rational a). Then a is in motor B's answer (Lemma 14) and its bounds of ln meet [A, B], so it is not removed.
    - *Why (I) is enough.* Each exact decision enumerates the pairs or derivations of entries that the interval machinery returns, and for each of them the combinations of the members of its entries. A value f(a, b) has entries i_a, i_b given by (I). Their statements hold for a and b, so by Lemma X2 the enclosure of the pair contains f(a, b): the pair is returned whenever f(a, b) is wanted, and (a, b) is among its combinations. This is the argument already used with the larger lists; only the lists changed.

49. **The exact resolution of |s − l| near each member of s (`qx.near_x_ys`, 16/11).** For a recursive l against a window with ln u ≤ −690, the exact members of l are asked for only near each exact member x of the class of s with u ≤ x/2: every member y with |x − y| = u has |ln y − ln x| ≤ 2u/x = d, so the query window is [ln x − d, ln x + d] (Arb, 256 bits, outward). When it contains 0 and x is exactly 1, the query is made twice with the second levels (±1, −∞, ln d) (y = 1 itself gives |x − y| = 0, never in the window); otherwise the general query is kept. Every pair (x, y) whose difference lies in the window is among those found. *Why:* the same pieces of splits 18–20 enumerated every member of V(345789) within 10⁻¹² of 1 (hours, more than 9 GB). *Test `t_nearx.py`:* 150 real cases of split 20 compared with the general query: 0 pairs meeting the window missing.

50. **Huge exact powers as terms of the linear forms, and integer powers of a form (`lvl.lin_mono`, `lvl.pw`, 17/11 — patch 6).** An exact power b^k (b a small rational, k an integer) too large to expand keeps its prime-exponent vector, and in a linear form a power whose integer part of the exponent is too large is kept whole in the key of its term (never expanded), so the same power always gets the same key. An integer power k ≤ 8 of a value with a linear form is the product of the form with itself, term by term. Then 3^(10⁷) − (9^(10⁶) + c)⁵ is an exact form in which the leading term cancels exactly; its value is enclosed term by term (item 46). *Why:* split 55 had |3^(10⁷) − (9^(10⁶) ± c)⁵|. *Test `t_lvlbin.py`:* X = B^k of 0.6–1.5·10⁶ bits, |T − q^m| with the true ln inside and decided outside a window at π, and q^m written twice gives the exact 0: 24 + 24 cases, 0 problems. **This item introduced the sign error described next.**

**The checker after patch 6: a sign error, and the rules of patches 7 and 7c (17–18/11).**

*The error.* Item 50 began to attach linear forms also to exact results that are huge rationals (more than 600 000 bits). In the subtraction, the form of a − b was turned into the form of |a − b| (by the order of a and b) only when the result was not exact. So |c − P|, with P a huge exact power and c < P, received the form c − P: the opposite of its value. Most of the time another exact rule decides first, but where a value is taken from its form (a form that cancels with no enclosure to check it, or the evaluation of a form after the other rules fail), a value inside the window could have been declared outside, without trace. Patches 4 and 5 do not have it: there a huge exact rational had no linear form, and forms were attached only to inexact results, where the sign was taken. It was found while studying the undecided values of the first cloud pass of n = 9 (57 distinct expressions, all |A − B| of huge numbers that are equal or almost equal).

*Negative control.* A test builds random trees of sums and differences of small rationals and huge exact powers and compares the form of every node with its exact value (Python fractions): with the checker of patch 6, 50 of 146 forms are wrong; with the corrected one, 0 (`t_lvlbound.py`, part 5). Since it cannot be known without re-evaluating the hits whether the error acted on any of them, every record made with the checker of patch 6 (fingerprint `d2ead1fb…`) was set aside and recomputed.

*Patch 7 (checker fingerprint `bc9d449d…`).*
- **The fix.** The sign of the form of |a − b| is taken from the order of a and b (certified, `_gt`) also when the result is a huge exact rational; when the order is not certified, no form is kept.
- **A barrier.** Before a form is attached to a value, its value (interval arithmetic) must be positive and its logarithm must meet the enclosure of the value's logarithm (`_form_agrees`). A form that fails is a defect of a rule; the operation fails, and the value stays undecided instead of being decided wrongly.
- **Bounds of |A − B| from the logarithms (`bound_diff`).** When no rule gives the difference, with d = ln A − ln B and A ≥ B: A − B = A(1 − e^(−d)) and d·e^(−d) ≤ 1 − e^(−d) ≤ d, so e^(min ln)·|d|_min·e^(−|d|_max) ≤ |A − B| ≤ e^(max ln)·|d|_max (the lower bound only when the enclosure of d excludes 0). The result can only be compared with a window; as an operand it is refused. If the two values also have an exact linear form of A − B, the form is used instead.
- **Anchored differences.** |q − a_q(1 + σe^D)| = |(q − a_q) − σa_qe^D| is bounded from its two exact pieces (ln(q − a_q) exact up to rounding, ln a_q + D), much tighter than the enclosures of the two values; an exact power known by its vector is compared with an anchor through its exact value.
- **x¹ keeps the exact forms of x**, which a new evaluation lost: (3^4194304 + 1/5)¹ − 9^2097152 = 1/5.
- **Roots of "power + constant" anchored at the exact power (`_root_of_offset`).** (aP + c)^t, t not an integer, with a·P + c the exact rational of the base (checked exactly) and c tiny relative to aP: (aP)^t(1 + c/(aP))^t, an anchor at the exact power (aP)^t; near_root (item 35) anchored at a rational close to the irrational root, and ((3^390625 + 3/5)^(1/10))⁴ against 9^78125 stayed undecided.
- **A further candidate of `near_root`:** the r-th power part of a denominator (or numerator) made of primes below 10⁴, and the r-th root of the rest: (10/3)^78125 + 4/5 = M⁵(1 + ρ) with M = (10/3)^15625.

**The independent evaluator `lvl.py`.** It does not contain this rule. A third generic mechanism was added on 03/11, for the hits of n = 9 that are differences of two equal powers written differently, such as (3^.2)^10000 and 43046721^125, both 3²⁰⁰⁰:
- *exact powers of primes:* `lvl` keeps, next to the interval, the vector of prime exponents of a value that is an exact power of rationals. The exponents may now be fractions: (∏ p^(a_p))^t = ∏ p^(a_p t). Large exact rationals made of primes below 10⁴ are factored by trial division.
- The vectors add under products and subtract under quotients. Two values are equal if and only if their vectors are equal, since the ln p are linearly independent over ℚ. A vector with a fractional exponent is irrational, so it differs from every rational.
- This is unique factorisation, implemented in `lvl.py` with its own code. It shares nothing with the triples of `ivl.py` (primitive roots, int64 fields) except the mathematics.
- Test `t_lvlpf.py`: 2000 pairs built as (b^t₁)^t₂ and b₂^t₃ with rational exponents. All 225 equal pairs give the exact zero, there is no false zero, and the other differences, products and quotients contain the mpmath value at 120 digits.
- *exact offsets:* a value X ± c, where X is an exact power (a vector) and c is any value of `lvl` (exact, or an enclosure such as 6^(−0.8)), keeps the relation exactly:
  - (X + c) + e = X + (c + e);
  - |e − (X ± c)| = X ± c − e when X ± c > e certainly, by the logarithms;
  - |(X + σ₁c₁) − (X + σ₂c₂)| = |σ₁c₁ − σ₂c₂|, computed again by `lvl`.

  Products and quotients combine the vectors before evaluating intervals, so 3^(2⁶²)/(1/3)^(−2⁶²) is exactly 1, with no subtraction of two logarithms of size 10¹⁸. The same test: 704 rational and 176 irrational offsets, 0 failures.

Both are plain arithmetic, exact or with interval rounding at a chosen precision, so a value that `lvl` places outside the window is outside. `t_lvl.py` (3000-digit references) passes at 400 and at 1600 bits.
